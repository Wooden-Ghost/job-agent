# 智联招聘采集 Agent —— 流程与逻辑

> 版本 0.1（2026-11-03）｜状态：**待确认，未开始编码**
> 定位：独立本地程序，**不依赖 DSH、不调用大模型**，只负责把智联 App 的数据搬进本地库。
> 数据落地后由 DSH（大模型）读库做分析与打分，两边彻底割裂。

---

## 0. 设计原则

1. **只做采集**。不做评分、不做判断、不做背调。唯一职责：把数据完整、干净、不重复地写进库。
2. **零 token**。采集全程不经过大模型。
3. **零外部依赖**。只要 `adb` + Python 标准库（已实测可行，不用 Playwright / uiautomator2 / OCR）。
4. **可分发**。打包后在任意 Windows + 安卓模拟器环境运行，换电脑只需改 `config.json`。
5. **可中断**。任何时候 Ctrl+C 或崩溃，重跑不会重复抓、不会丢已抓数据。

---

## 1. 输入

| 项 | 来源 | 说明 |
|---|---|---|
| 采集入口 | 首页 3 个求职期望 tab | 用户在 App 内配好：`Python` / `数据采集` / `爬虫`；程序启动时自动读取 tab 名，**不硬编码** |
| 抓取深度 | `config.json` 的 `screensPerTab` | 每个 tab 往下滑几屏，默认 3 |
| 关键词（可选） | `config.json` 的 `keywords` | 仅 ASCII 可用（`input text` 打不进中文）；默认留空，只吃期望 tab |
| 单次上限 | `maxJobsPerRun` | 防跑飞，默认 60 |

---

## 2. 页面状态机

只有 4 个状态，识别靠「锚点文字」，不靠坐标：

| 状态 | 识别锚点 | 下一步 |
|---|---|---|
| `HOME` | 含 `搜索职位/公司` 且含底部 `首页` | 切 tab |
| `LIST` | 有 ≥1 张卡（同时有 薪资 与 公司） | 抓卡片 / 滑屏 / 进详情 |
| `DETAIL` | 含 `立即投递` 或 `先聊聊` | 抽字段 → BACK |
| `UNKNOWN` | 以上都不满足 | 复位：BACK ×3（每次隔 1–2 秒）→ 仍不行则 `am start` 回首页 → 仍不行则**停机并写日志** |

坐标一律从 dump 里的 `bounds` 取中心再随机抖动，**不写死像素**（写死会在换分辨率/换版本时全崩）。

## 3. 采集主流程

```
启动
 └─ 环境自检（adb 在不在 / 设备连不连 / App 在不在）
     └─ 回 HOME
         └─ for tab in tabs:
             ├─ 点 tab，等 LIST
             ├─ for i in range(screensPerTab):
             │    ├─ dump → 解析卡片 → 全部暂存内存（不进库）
             │    └─ 随机滑动，等 0.8–2 秒（模拟"看一眼"）
             └─ for card in 本次新卡片:      ← 先抓完列表再统一进详情
                  ├─ 按唯一键查库，已存在 → 跳过（0 次点击）
                  ├─ 点进 → 等 DETAIL 锚点（最长 15 秒）
                  ├─ dump 一次 → 抽 JD 全文 + 公司四要素
                  ├─ 写库（立刻 commit）
                  └─ BACK → 等 LIST
```

**为什么"先抓完列表再进详情"**：真人就是这个顺序——先扫一遍列表，再挑感兴趣的进去看。交替进出详情页在行为上非常异常。

**为什么"进详情前先查库"**：老岗位重复点进去是最容易暴露的模式（同样的岗位反复点开）。

## 4. 字段设计

### 列表页可拿到（不用进详情）

`title` `salary` `company` `companySize` `companyStage` `tags` `hr` `activity` `area`

### 详情页可拿到（进详情才有）

`jd`（全文，实测 190–900 字符一个节点给全）`companyFull` `companyMeta` `city` `hiringCount` `location` `experience` `education`

### 表结构（`jobs`）

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `job_key` | TEXT PK | 计算 | `sha1(companyNorm + '\|' + titleNorm)[:16]` |
| `source` | TEXT | 常量 | `zhaopin` |
| `tab` | TEXT | 采集 | 该条来自哪个期望 tab |
| `title` / `title_norm` | TEXT | 列表 | |
| `company` / `company_norm` | TEXT | 列表+详情 | 规范化规则复用 `公司名规范化.py` |
| `company_full` | TEXT | 详情 | 工商全称（可能为空） |
| `salary_text` | TEXT | 列表 | 原样，如 `8000-12000元·13薪` |
| `salary_min` / `salary_max` | INT | 解析 | 解析失败留 NULL，**不猜** |
| `city` / `district` | TEXT | 详情 | |
| `area_text` | TEXT | 列表 | 如 `成都 武侯 桂溪` |
| `experience` / `education` | TEXT | 详情 | |
| `company_meta` | TEXT | 详情 | 如 `民营·20-99人·产业互联网平台` |
| `company_size` / `company_stage` | TEXT | 列表 | |
| `hiring_count` | TEXT | 详情 | 如 `在招4个职位` |
| `jd` | TEXT | 详情 | 全文 |
| `jd_len` | INT | 计算 | |
| `first_seen` / `last_seen` | TEXT | 时间 | ISO8601 本地时间 |
| `seen_count` | INT | 计数 | 同一条被重复抓到的次数 |
| `raw` | TEXT | 原始 | 整条 JSON，便于回溯与重新解析 |

**留 NULL 的原则**：取不到就留空，绝不写「待补」「未知」这类字符串——留空下游才能判断是缺失。

## 5. 去重与断点续跑

- 唯一键：`sha1(companyNorm + '|' + titleNorm)[:16]`（已验证：同公司不同岗不同键、同岗同公司同键）
- 已存在 → **只更新 `last_seen` / `seen_count`**，不进详情、不花时间
- 每写一条立刻 `commit`，所以随时 Ctrl+C 都安全
- 崩溃后重跑自动跳过已有键（断点续跑）

---

## 6. 随机化（反自动化）——硬性要求

全部集中在一个 `humanize` 模块，不允许在业务代码里散写 `sleep`：

| 动作 | 规则 |
|---|---|
| 一般等待 | `random.uniform(1.2, 3.5)` |
| 关键页等待（详情/期望） | `random.uniform(3.0, 6.0)` |
| 点击落点 | 控件 `bounds` 内随机取点，四边留 8% 边距 |
| 滑动 | 起止 y 随机 ±150、x 随机 ±40、时长 `random.randint(280, 520)` ms |
| 长停 | 每 5–8 条插一次 `random.uniform(20, 60)` 秒 |
| 条目顺序 | 详情阶段随机打散（不永远从前 3 条开始） |
| tab 顺序 | 每次运行随机打散 |
| 运行时长 | 超过 `maxRunMinutes` 自然收尾（不是硬切） |

**禁止项**：不 `force-stop` 用户的 App、不并发多实例、不绕验证码、不改机。

## 7. 异常处理

| 情况 | 处理 |
|---|---|
| dump 返回 0 节点 | 重试 3 次（间隔 1.2 秒）；仍失败 → 记 `dump_fail` 计数，转 UNKNOWN 复位 |
| 连续 3 次 dump 失败 | **停机**，写日志，退出码 2 |
| 详情页 15 秒没等到锚点 | BACK 放弃该条，记 `detail_timeout`，继续下一条（这条下次重跑会再试） |
| 滑一屏 0 条新增 | 停 3 秒重读一次，仍 0 → 认定到底 |
| 出现未知页 | 复位 3 次，仍未知 → 停机 |
| 网络错误页 | 同上（识别：出现 `网络` + `重试` 类文字） |

所有异常都记 `logs/run-YYYYMMDD-HHMMSS.jsonl`，一行一个事件。

### 实测结果

| 轮次 | 配置 | 入库 | 失败 | 耗时 | sameCard |
|---|---|---|---|---|---|
| 1 | 1 屏 / 上限 2 | 2 | 0 | 31 s | **False（踩坑）** |
| 2 | 2 屏 / 上限 3 | 3 | 0 | 45 s | True |
| 3 | 1 屏 / 上限 4 | 4 | 0 | 47 s | True |

字段完整度：`title / company / salary_text / city / district / experience /
education / company_size / jd` 全部有值；JD 199–479 字符为真实全文。

### 实测踩到的 3 个坑（均已修）

1. **滚回顶部会触发下拉刷新**。原设计是「先滑 N 屏收完列表、再滚回顶部逐条点开」。
   实测发现滚回顶部的那一下被当成下拉刷新，列表重排 → 点开的是别的岗位，
   `raw.list` 与入库的那个岗位对不上（`sameCard=False`）。
   **改为边滑边点**：抓完一屏立刻点这一屏的卡，坐标永远新鲜，不再滚回顶部。
   另外加了 title 前 6 字比对，不一致时列表独有字段（area/company_size/
   company_stage）一律丢弃，防止串行。

2. **「工作城市」拿错了**。详情页「公司信息」里的城市是**公司注册地**
   （湖南公司在成都招人 → 显示「长沙」），不能当岗位城市。
   现在 `city` = 列表卡区域首段（3 段时）否则 config `defaultCity`，
   公司注册地另存 `company_city`。

3. **tab 定位不能靠绝对坐标**。首页有搜索框时 tab 在 y≈164，结果页没有搜索框时
   在 y≈80；用固定区间会把城市选择页的「成都」标题当成 tab 点进去。
   改为**相对锚点**：先找「全部/最新/附近」那一行，tab 就在它上方 30–130px。

## 附：已验证的技术事实（来自 `智联自动化-实测说明.md`）

- 读界面：`uiautomator dump` **落盘再 `exec-out cat`**（`/dev/tty` 不稳），返回完整控件树
- 截图：必须 `cmd /c "adb exec-out screencap -p > x.png"`
- 详情页：一次 dump 拿全 JD 全文 + 公司四要素，**不用滚动、不用 OCR**
- 中文：`input text` 只能 ASCII；期望 tab 本身就是中文入口，无需额外输入法
- 列表翻页：滑完 0 卡 ≠ 到底，需停 3 秒重读
